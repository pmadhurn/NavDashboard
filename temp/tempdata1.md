## CORE FEATURES

- **CRUD** on all entities: devices, couples, pairs (add, edit, delete)
- **Status tracking**: Working (green) / Not Working (amber) / Faulty
  (red) — manually set, color-coded
- **Handling person** assigned to each device/couple/pair
- **Error & troubleshooting history** per device/couple/pair — highly
  customizable (JSONB custom fields)
- **Current location** per couple — stored as coordinates (PostGIS)
- **Map visualization** — Leaflet + OpenStreetMap; view, select, place
  devices on map
- **Location history** — when location changes, old location is archived
  with: timestamp, handling person, couple configuration (with/without
  RF), distance, fitting materials used at that location
- **Suggestive completion** — when creating new couples, suggest/copy

- **Configuration Comparison** — side-by-side config diff of two
  couples/pairs
- **Dashboard & Analytics** — stats cards, pie charts, bar/line graphs,
  error trends
- **Audit Trail** — every CRUD action logged (who, when, what changed,

- **Report Generation** — export PDF/Excel reports
- **Advanced Search** — full-text search across all entities, filter by
  any field
- **Document Attachments** — attach files/images/manuals to any entity

  troubleshooting history, configs, etc.) via vector embeddings

- **Backup & Restore** — two modes available in frontend:
  1. pg_dump / pg_restore (full DB, best for server migration)

BUSINESS RULES (MANDATORY)
A device can belong to only ONE couple at a time.
Assigning to a new couple auto-unassigns from the old one.
A couple can belong to only ONE pair at a time.
Deleting a couple: soft-delete the couple, set all its
devices' couple_id to NULL, remove from pair if assigned.
Deleting a pair: soft-delete the pair, set both couples'
pair_id to NULL. Do NOT delete the couples.
All queries automatically exclude soft-deleted records
(WHERE deleted_at IS NULL) UNLESS specifically requesting
deleted items (e.g., audit trail views).
Serial numbers are globally unique across all device types.
Status changes ALWAYS create a history record (DeviceStatusHistory
or StatusChangeLog).
Location changes ALWAYS create a LocationHistory record
with a snapshot of current configuration and materials.
Embedding sync runs as a Celery task, triggered on data
mutations and available manually via API.
XLSX/CSV import uses upsert logic: match by ID if present,
otherwise match by serial_number/name, otherwise create new.
A pair must have exactly 2 couples. Cannot save with 0, 1, or 3+.
If either couple in a pair is FAULTY, the pair's auto-derived
status is FAULTY. Manual override is allowed.
Default admin account (admin@navdashboard.local / admin123) is
created only on first startup when no users exist. A warning is
logged to change the password.
